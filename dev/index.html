HyperRVE.jl

Periodic representative volume element (RVE) meshes with the Gmsh Julia API: describe a Cell, fill it with Phases built from primitives, booleans and transforms, and call generate.

using HyperRVE
cell = Cell((1.0, 1.0, 1.0))
rve  = RVE(cell, Phase(:particles, [Sphere((0.5, 0.5, 0.5), 0.25), Sphere((0, 0, 0), 0.25)]; refine = 0.03))
res  = generate(rve; h = 0.1, output = "bcc.msh")
volume_fraction(res, :particles)          # ≈ 0.131
  • cells of any size and origin, 2D and 3D, mixed periodicity, supercells;
  • periodic images of inclusions crossing faces, edges and corners, items larger than the cell;
  • phases painted in order, porous media without matrix;
  • interface refinement with a periodic size field, phase sizes, order-2 elements, quality report;
  • physical groups for phases, cell faces/edges/corners and interfaces, ready for GridapGmsh.

See the User guide, the Examples and the migration notes for scripts written for the 2024 API.

HyperRVE.HyperRVE — Module
HyperRVE

Periodic representative volume element (RVE) meshes with the Gmsh Julia API.

Describe a cell (Cell), the phases inside it (Phase) built from geometric primitives, booleans and transforms, wrap everything in an RVE and call generate. Periodic images of inclusions crossing the cell boundary, phase assignment, physical groups and periodic meshing are handled automatically.

HyperRVE.GapRefinement — Type
GapRefinement(; elements = 2, faces = true, growth = nothing)

Refinement of the thin gaps between spheres or disks (any phases, void ones included) and, with faces = true, between them and the cell faces: elements elements across each gap at its narrowest point, the size following the local width of the ligament and growing with growth (default MeshOptions.growth) into the inclusions. Only gaps narrower than the smaller radius and than elements times the bulk size act, and only with a matrix (without one the gaps are empty). A gap cut by a periodic face counts as two halves (elements / 2 between the inclusion and the face, at least 1). Use it as MeshOptions(gaps = 2) or MeshOptions(gaps = GapRefinement(elements = 3)), with the :delaunay (default) or :hxt 3D algorithm; optimize = :netgen removes the occasional sliver in a ligament.

HyperRVE.InterfaceRefinement — Type
InterfaceRefinement(; h = nothing, level = 1.0, width = nothing, growth = nothing)
InterfaceRefinement(h; kwargs...)

Mesh refinement on the interfaces of a phase (the surfaces it shares with other phases, not the cell faces). HyperRVE.MeshOptions — Type
MeshOptions(; h = nothing, hmin = nothing, hmax = nothing, growth = 1.3, curvature = nothing,
            periodic_sizes = true, order = 1, curved = true, algorithm = :default,
            surface_algorithm = :default, optimize = :auto, optimize_curved = :auto, gaps = nothing)

Global meshing options, all lengths in the units of the cell.

  • h: element size in the bulk of the phases (default: smallest cell edge / 10). A phase can override it with Phase(...; h = ...).
  • hmin, hmax: hard lower and upper bounds of every element size.
  • growth: ratio between the sizes of neighbouring element layers away from a refined interface (the size grows linearly with the distance, slope growth - 1).
  • curvature: minimum number of elements per 2π along curved boundaries: near a boundary of radius of curvature R the size is at most 2πR/curvature, so that inclusions smaller than h are still resolved (default 6, which only acts where R < h; 12 for curved order-2 meshes; 0 disables it).
  • periodic_sizes: make the size field periodic (refinement near a face also refines the opposite face). Each refined interface is evaluated at up to 3^D - 1 shifted points, so meshing with refined inclusions takes about 1.5-5 times longer than without it (a larger growth shortens the transitions and reduces the cost). Only meant to be switched off for comparisons.
  • order: 1 (linear) or 2 (quadratic elements; with curved = true the mid-nodes lie on the curved interfaces, with curved = false the elements are straight-sided). Order-2 meshes are periodic in Gmsh's sense, but GridapGmsh (0.7) reads periodic links only for first-order meshes: for Gridap/HyperFEM with periodic cells, generate an order-1 mesh and use higher-order finite element spaces on it.
  • algorithm: 3D mesher, :delaunay (default), :frontal or :hxt; surface_algorithm: :default, :frontal, :delaunay, :meshadapt or :automatic (also used for 2D cells). :default is Frontal-Delaunay, with MeshAdapt on the B-spline surfaces (ellipsoids, bodies transformed with Scale) of inclusions inside the cell, where Frontal-Delaunay gives poor elements, and on any surface Frontal-Delaunay leaves without elements (Gmsh 4.15). With an explicit algorithm there is no such fallback; an incomplete mesh is always an error.
  • optimize: optimisation of the linear mesh, :default (true), :netgen or :none (false); :auto (default) is :netgen for curved order-2 meshes (it removes the linear elements that would become inverted once curved) and :default otherwise. The Netgen optimiser acts with the :delaunay and :frontal algorithms (not with :hxt).
  • optimize_curved: untangling of curved order-2 elements. :auto (default) is :elastic for curved order 2 and :none otherwise; :elastic removes inverted curved elements and keeps the periodic faces matching; :optimize (Gmsh's general optimiser) moves nodes of periodic faces, so it is only accepted for cells without periodic directions; :none leaves the curved elements as projected (coarse meshes may then contain inverted elements: generate warns and res.stats.ninverted counts them).
  • gaps: refinement of the thin gaps between spheres or disks and between them and the cell faces, so that a ligament gets gaps elements across instead of one flattened element: a number of elements, true (2) or a GapRefinement. Much cheaper than refining the whole phase: the size follows the local width of the ligament.

HyperRVE.Phase — Type
Phase(name, geometry; h = nothing, refine = nothing, fuse = false, void = false)

A named material phase. geometry is one Geometry or a collection of them (the items of the phase). By default items are not fused: where items of the same phase overlap (or overlap their own periodic images) the mesh keeps the internal surfaces, which all belong to the phase; fuse = true (below) removes them. Each item crossing a periodic face of the cell is completed with its periodic images.

  • h: element size inside the phase (default: the global size of generate).
  • fuse: unite the items of the phase and their periodic images into one body before meshing, so that no internal surfaces remain where items overlap (strut lattices, overlapping particles). Refinement by level then uses the smallest item of the phase, and overlaps = :error only compares different phases (items of a fused phase may overlap).
  • void: the phase is empty space: what it covers (painted over the earlier phases and the matrix) is removed from the mesh, and its surfaces become interface_<a>_void groups. Pores, holes and closed-cell foams: Phase(:pores, items; void = true). A void phase has no h or refine, and is not listed in the result.
  • refine: refinement on the interfaces of the phase: a size (refine = 0.02), true (the rule of the 2024 API), a NamedTuple of InterfaceRefinement keywords or an InterfaceRefinement.

HyperRVE.RVE — Type
RVE(cell, phases; matrix = :matrix, tiling = 1, overlaps = :paint)

Description of a representative volume element: a Cell filled with a background phase called matrix (or nothing, matrix = nothing, for porous media and lattices) and the given Phases. Where phases overlap, the phase listed later wins (overlaps = :paint); overlaps = :error makes any overlap an error.

tiling = n (an integer or one per direction) meshes a supercell made of n copies of the cell along each direction: the items of the phases are given for one cell and translated by every cell offset of the supercell. Along periodic directions the supercell is periodic. Along non-periodic directions nothing wraps around: an item is cut only by the outer faces of the supercell, so an item that sticks out of the unit cell (or lies outside it) appears, whole, in the neighbouring copy where it falls inside the supercell. See also supercell.

HyperRVE.chiral — Method
chiral(cell::Cell{2}, kind; ring_radius, thickness, mirror = false, filled = false)

Items of a chiral or anti-chiral lattice: rings of mean radius ring_radius and wall thickness, joined by straight ligaments of the same thickness tangent to the rings (outer radius ring_radius + thickness / 2). kind is :hexachiral, :tetrachiral, :trichiral, :antitetrachiral or :antitrichiral; the cell must be periodic with the proportions of lattice_cell(kind), whose a is the distance between the centres of connected rings. mirror = true gives the mirror image (opposite handedness); the anti-chiral lattices are their own mirror image, so for them it only moves the lattice. filled = true gives solid disks instead of rings. Use them in a fused phase: Phase(:lattice, chiral(c, :hexachiral; ring_radius = 0.2, thickness = 0.04); fuse = true). The exact solid fraction is relative_density(kind; ring_radius, thickness, a).

HyperRVE.dense_spheres — Method
dense_spheres(cell; radius, fraction, n, min_gap = 0, rng = Random.default_rng(),
              strict = true) -> Vector{Sphere} (3D) or Vector{Disk} (2D)

Non-overlapping spheres (disks in 2D) packed much denser than random_spheres: the spheres start small at random positions and grow while their overlaps are relaxed. Fractions up to about 0.6 (3D) and 0.75 (2D, equal disks; more with a size distribution) are reached; random sequential addition stalls at about 0.38 and 0.55. The spheres are returned largest first (as in random_spheres). radius, fraction and n follow the rules of random_spheres: exactly two of them, or a vector of radii, or a sampler rng -> r with fraction or n.

  • Along periodic directions the spheres may cross the faces (generate completes them); along non-periodic directions they stay inside the cell.
  • min_gap: minimum distance between sphere surfaces.
  • If the packing jams before reaching the requested radii, strict = true throws an error with the fraction reached; strict = false warns and returns the spheres scaled down to it (keeping min_gap; an error if the smallest spheres would vanish).

The result is meant both as an inclusion phase and as the seeds of a laguerre tessellation (laguerre(cell; spheres = dense_spheres(...))).

source
HyperRVE.foam_struts — Method
foam_struts(t; radius, node_radius = :auto, min_length = nothing) -> Vector{Geometry{3}}

Open-cell foam: the edges of a fully periodic tessellation as struts (one Cylinder per edge and one Sphere per vertex, see struts). Edges shorter than min_length are collapsed first (their vertices merged; min_length = nothing means 2 radius), since a strut shorter than its diameter is buried in the node spheres. Use in a fused phase without matrix: RVE(cell, Phase(:foam, foam_struts(t; radius = 0.02); fuse = true); matrix = nothing). Practical for about 5–20 cells (the fused union of the struts dominates the cost).

         check_periodicity = true, view = false, keep_open = false, verbosity = 0,
         name = "RVE") -> RVEMesh
generate(f, rve; kwargs...)

Build the geometry of rve in Gmsh, assign phases, create physical groups, impose periodicity and mesh it. Gmsh is initialised and finalised automatically; the returned RVEMesh is plain Julia data.

  • h: global element size (shorthand for mesh = MeshOptions(h = h)); it is reduced near inclusions with refinement and near boundaries of small curvature radius (see MeshOptions).
  • output: file name or vector of file names written before Gmsh is closed (.msh, .vtk...).
  • geometry_only: stop before meshing (volumes and groups only; fast).
  • check_periodicity: verify node by node that opposite periodic faces have matching meshes (throws PeriodicityError otherwise).
  • view: open the Gmsh GUI before returning (skipped with -nopopup or RVES_NOPOPUP=1).
  • keep_open: leave Gmsh initialised so that write_mesh and view_mesh can be used; close it with close_gmsh.
  • verbosity: 0 silent, 1 summary, 2 Gmsh terminal output.
  • name: name of the Gmsh model (made unique if a model with that name is already open).
  • interfaces: create the interface physical groups (see below); :union creates only their union interfaces (for many phases, e.g. polycrystals: the result still lists every interface).

The do-block form runs f(res) while the Gmsh model is alive, then closes Gmsh (unless keep_open = true); it returns res, not the value of f. In the live model the mesh is in physical coordinates but the CAD entities are in a normalised frame (domain origin at 0, longest edge 1): use write_mesh, not gmsh.write, to export it. Each call adds a new Gmsh model to an open session (names made unique); call close_gmsh to free them.

Gmsh is initialised without reading the user configuration files, and .msh files are written in format 4.1. If the caller already initialised Gmsh, that session is left open and the options changed by generate are restored on return.

Physical groups: one per phase (dimension D; matrix tag 1, phase i tag 1 + i), and on the cell boundary xmin, xmax, ymin, ymax, zmin, zmax (tags 1-6, closed faces, defined in every lower dimension), corners (7), boundary (8), edge_<face>_<face> (11-22, 3D only) and corner_<x>_<y>[_<z>] (31-38). Interfaces between phases (surfaces not on the cell faces whose two sides belong to different phases; one side void for free surfaces without matrix) get the groups interface_<a>_<b> (phases in the order of phase_names(res); with N phases including the matrix and i < j their positions, void being N + 1, the tag is 100 + (i-1)(N+1) + j) and their union interfaces (tag 99), defined in dimensions D-1 to 0 (closed sets; closed surfaces such as a whole sphere contribute their seam curve and poles). In Gridap, BoundaryTriangulation(model; tags = "interface_a_b") gives the interface facets with the cells of one side chosen by Gridap (the orientation of the normal is not controlled: fine for areas, Dirichlet data and integrals of scalar facet quantities). For a one-sided trace use BoundaryTriangulation(Triangulation(model, tags = "a"); tags = "interface_a_b"); for jumps and normals oriented from one phase to the other use InterfaceTriangulation(Triangulation(model, tags = "b"), Triangulation(model, tags = "a")) (plus side in b), which does not need the interface groups. Facets on an interface carry the interface labels instead of the phase labels. In 2D the faces are the four sides of the cell (curves and points) and the mesh is made of triangles in the plane z = 0. Groups without entities are not created: with matrix = nothing the cell faces exist only where the phases touch them, and a periodic direction without any entity on its faces is reported with 0 pairs.

When a periodic mesh is read by GridapGmsh, master and slave entities are identified, so the labels xmin/xmax (and the corner_*, edge_* groups) of a periodic direction are shared between both sides and are not reliable as boundary tags; in periodic directions use corners (e.g. to fix rigid-body motions) and the phase names.

HyperRVE.particle_chains — Method
particle_chains(cell; axis = D, radius, gap, fraction = nothing, n_chains = nothing,
                arrangement = :random, chain_gap = :auto, face_gap = :auto, fit = :gap,
                stagger = :random, occupancy = 1.0, waviness = 0.0, modes = 2, aspect = 1.0,
                rng = Random.default_rng(), max_tries = 50_000, strict = true)

Chains of spheres (disks in 2D) aligned along the cell axis axis: the microstructure of field-structured magnetorheological elastomers. Returns the particles chain by chain, in increasing axial coordinate; use them in a phase without fuse.

  • radius: a number, a vector (one radius per chain) or a sampler rng -> r (one per chain); gap (> 0): minimum surface distance between consecutive particles of a chain.
  • fraction (particle volume fraction) or n_chains (with :square/:hex also (n1, n2)); with a vector of radii, neither.
  • arrangement: :random (random sequential addition of the chain axes in the cross-section), :square or :hex (in 2D :regular). chain_gap (default max(gap, 0.1 r)): minimum distance between the envelopes of two chains; face_gap (default chain_gap): bands to the faces, as in random_spheres.
  • Along a periodic axis the chains are infinite: fit = :gap takes as many particles as fit and spreads the rest of the length over the gaps (the gap only grows; a warning above 1.5×), fit = :strict requires a commensurate length. stagger: axial offset of each chain in units of the pitch (:random, a number in [0, 1), or :alternate for regular arrangements: neighbouring chains shifted by half a pitch).
  • occupancy < 1 removes particles at random (broken chains); waviness (in units of the radius) bends the chains with modes smooth periodic modes (the in-chain gap never decreases); aspect ≠ 1 gives spheroids (ellipses) elongated along the chain.

Reachable fractions with gap = 0.1 r: about 0.28 with random chains, 0.45 square, 0.52 hexagonal. fraction is counted before occupancy. Wavy chains are packed with their amplitude as extra clearance, which leaves a thin particle-free layer next to periodic faces. stagger = :alternate alternates neighbouring chains only for even counts along periodic directions, and only along a periodic chain axis. Along free lateral faces the chains may be cut by the face, as the inclusions of random_spheres. Mesh: the ligaments between particles of a chain have the width gap; MeshOptions(gaps = 2) puts two elements across every thin gap and keeps the rest coarse (refining the whole phase with refine = gap / 2 also works but costs 10–50 times more elements).

HyperRVE.random_capsules — Method
random_capsules(cell; length, radius, fraction, n, orientation = :isotropic, axis = 3,
                min_gap = :auto, face_gap = :auto, boundary = :periodic, avoid = nothing,
                rng = Random.default_rng(), max_tries = 50_000, strict = true) -> Vector{Capsule}

Random short fibres: non-overlapping capsules (cylinders with hemispherical ends) of radius radius placed by random sequential addition. length is the distance between the centres of the two caps (total length length + 2 radius): a number with fraction or n (exactly one), a vector of lengths, or a sampler rng -> length with fraction or n.

  • orientation: :isotropic (uniform on the sphere), :planar (uniform in the plane normal to axis), a direction (x, y, z) (all aligned with it), a 3×3 second-order orientation tensor A (symmetric, positive semidefinite, trace 1; directions drawn from the central angular Gaussian with that second moment, so orientation_tensor of many fibres tends to A) or a function rng -> direction.   • The fibres are returned from the longest to the shortest.
  • min_gap (default 0.1 radius), face_gap (default min_gap), boundary, avoid, rng, max_tries and strict as in random_spheres. The bands to the faces reject fibres whose surface, cap junctions or cap poles nearly touch a face, edge or corner.
  • fraction is the volume fraction of whole capsules (fibres crossing free faces are cut).

Random sequential addition of equal capsules with the default gap reaches about 0.26, 0.19, 0.15 and 0.09 (isotropic) and 0.33 to 0.31 (aligned) for total aspect ratios (length + 2r) / 2r of 2, 5, 10 and 20; above that an error reports what was placed. HyperRVE.random_spheres — Method
random_spheres(cell; radius, fraction, n, min_gap = :auto, face_gap = :auto,
               boundary = :periodic, avoid = nothing, cluster = nothing,
               rng = Random.default_rng(), max_tries = 50_000, strict = true) -> Vector{Sphere}

Non-overlapping spheres placed by random sequential addition. Give exactly two of radius, fraction and n; or radius as a vector of radii; or radius as a function rng -> r (size distribution) with fraction or n.

  • min_gap: minimum distance between sphere surfaces (default 0.1 * the smallest radius).
  • face_gap (default min_gap): spheres nearly tangent to a face, edge or corner of the cell, or with the centre nearly on a face plane, are rejected (these give slivers and Gmsh periodicity failures). face_gap = 0 switches it off.
  • boundary = :periodic: spheres cross the faces and generate completes them; :inside: every sphere stays face_gap away from the faces (no cut spheres; leaves a depleted layer near the walls). Along non-periodic directions there is no wrap-around: with :periodic the spheres may cross those faces and are cut there, so the fraction inside the cell is somewhat below fraction (use :inside to keep them whole).
  • With a radius sampler and fraction, radii are drawn until the next one would exceed the target: the packing stays at or below fraction. volume_fraction(items, cell) gives the value of the returned inclusions.
  • avoid: geometries already placed (another population, particle_chains, items made by hand; a geometry, a vector, or a tuple of vectors) that the new inclusions keep min_gap away from (the min_gap of this call, by default 0.1 times its smallest radius), periodic images included. Exact for spheres, disks, capsules and fibres parallel to a cell axis; cylinders, ellipsoids and ellipses are replaced by the capsule that contains them (conservative: for flat ellipsoids it is a sphere). Mixtures: one call and one phase per population, largest first, each fraction of the whole cell: soft = random_spheres(cell; radius = 0.05, fraction = 0.05, avoid = hard).
  • cluster = (n = 4, radius = 0.2): clustered inclusions. n cluster centres are drawn uniformly (or given as centers = [...]) and each inclusion is placed uniformly in the ball of radius radius around one of them; with share = s < 1 only a fraction s of the attempts (not of the inclusions) go to the clusters and the rest to the whole cell. The cluster radius must be below half the cell; with boundary = :inside clusters do not wrap across the faces.
  • rng: an AbstractRNG or an integer seed; same seed and Julia version, same packing.

Achievable fractions with equal spheres: about 0.35 (min_gap = 0), 0.30 (0.1 r), 0.26 (0.2 r). Above that an error reports what was placed (strict = false: a warning and the partial packing). Put the result in a phase without fuse: Phase(:particles, random_spheres(cell; radius = 0.1, fraction = 0.2, rng = 1)).

Items of a strut lattice: one Cylinder per strut and one Sphere per node (in a 2D cell: a rectangle of width 2 radius per strut and a Disk per node; thickness = 2 radius may be given instead of radius).

  • edges: (i, j) joins nodes i and j of the cell; (i, j, (o1, o2, o3)) joins node i to the copy of node j in the cell shifted by o cells. List each strut once: periodic images are created by generate.
  • radius: one number or one per strut. node_radius: :auto (largest radius of the struts meeting at the node), a number, one per node, or nothing (no node spheres).

Along non-periodic directions every translate of a strut or node that overlaps the closed cell is emitted (a strut crossing a face appears at both faces, cut by them), so the lattice is the complete finite truss. Use the items in a fused phase: Phase(:lattice, struts(...); fuse = true).

HyperRVE.tpms — Method
tpms(kind; type = :sheet, density = nothing, level = nothing, periods = 1, resolution = nothing) -> TPMS

Experimental: a triply periodic minimal surface solid for a cubic periodic cell, with periods periods per side, kind one of :gyroid, :schwarz_p, :diamond, :iwp, :neovius, type = :network (solid f ≤ level) or :sheet (wall |f| ≤ level), and either the relative density (see tpms_level) or the level. resolution is the number of grid cubes per period of the triangulated surface (by default 24, raised for thin walls), which is meshed as it is (Gmsh fills the volumes): it sets the surface mesh size, h in generate only the size inside.

The TPMS must be the only item of the only phase, with a matrix or matrix = nothing, in a cubic cell periodic in the three directions, without tiling (use periods), h, refine, fuse, void or order 2:

rve = RVE(Cell((1.0, 1.0, 1.0)), Phase(:gyroid, tpms(:gyroid; type = :sheet, density = 0.3)))
res = generate(rve; output = "gyroid.msh")

The groups are those of other RVEs: the phases, interface_<matrix>_<phase> (or interface_<phase>_void, closed: with its curves and points on the faces), the faces xmin … zmax, boundary, corners, corner_* and edge_*. The $Periodic section of .msh files (MSH 4.1, also with write_mesh) pairs every node of opposite faces; GridapGmsh reads it. Only h of the mesh options is used.

HyperRVE.tpms_density — Method
tpms_density(kind; type = :sheet, level, periods = 1, resolution = nothing)

Relative density (solid volume fraction) of a triply periodic minimal surface solid in a cubic cell with periods periods per side: type = :network is the solid f ≤ level, :sheet the wall |f| ≤ level, with f the level-set function of kind (:gyroid, :schwarz_p, :diamond, :iwp, :neovius) over one period [0, 2π]³. The solid is the faceted surface of a periodic marching-tetrahedra grid of resolution cubes per period (by default 24, raised until the walls are 2.5 cubes thick), smoothed onto the surface: the one that is meshed. Its density converges as O(h²). Networks that do not connect across the cell raise an error. Experimental.

source
HyperRVE.tpms_level — Method
tpms_level(kind; type = :sheet, density, periods = 1, resolution = nothing) -> level

Level of tpms_density that gives the relative density, by bisection on the volume of the faceted solid (to about 1e-4: the volume jumps by ~1e-5 when the grid topology changes). Networks below their pinch-off (e.g. Schwarz P below about 0.21) do not connect across the cell, and walls too thin for the grid cannot be triangulated: both raise an error. Experimental.

HyperRVE.voronoi — Method
voronoi(cell; n = nothing, seeds = nothing, min_distance = :auto, lloyd = 0,
        periodic = cell.periodic, rng = Random.default_rng(), max_tries = 50_000) -> Tessellation

Periodic Voronoi tessellation of the cell with n random seeds or the given seeds (physical points). Random seeds are at least min_distance apart (:auto = half the mean grain size, 0 = Poisson–Voronoi). lloyd = k moves the seeds k times to the centroids of their grains (more uniform grain sizes). periodic = true on a cell with free faces gives a block cut from a periodic tessellation (its grains are clipped at the free faces). rng: an AbstractRNG or an integer seed; max_tries: attempts of the seed placement.

Vertices closer than 2e-7 of the cell are merged (the faces they touch are then split into triangles, identically in both grains). Seeds on a slightly perturbed regular lattice give grain faces nearly coplanar with the cell faces, which Gmsh may fail to make periodic.

Then RVE(cell, grain_phases(t); matrix = nothing) gives a polycrystal with one phase per grain and the grain boundaries as interface groups.

HyperRVE.write_mesh — Method
write_mesh(res, path)

Write the mesh of a live result (inside generate(rve) do res ... end, or after generate(...; keep_open = true)). The format follows the extension (.msh, .vtk, ...); .msh and .msh4 files are written in MSH 4.1 ASCII with the periodic links in physical units (other Gmsh extensions such as .msh2 select other formats and are written as Gmsh does, without that correction).

Use write_mesh rather than gmsh.write: the model is built in a normalised frame (the CAD entities stay in it, only the mesh nodes are mapped back to physical coordinates), so a .msh written directly with gmsh.write stores periodic maps in frame units and Gmsh would misplace the periodic nodes when reading it back.
